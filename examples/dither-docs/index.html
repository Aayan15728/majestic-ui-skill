Motion

How animated dithers run, pause and hold still, including under reduced motion.

Animated dithers in Grainkit are slow on purpose. A background should drift, not perform. Every animated component follows the same four rules, and they live in grain-core, so a dither you write yourself gets them for free.

import { DitherField } from "grainkit";

export default function Hero() {
  return (
    <DitherField
      palette="periwinkle"
      cell={6}          // px per dot
      speed={0.12}      // cells per second
      fps={12}          // redraws, not animation frames
      pauseOffscreen    // default: true
    />
  );
}

When a dither moves

A dither animates only while it is on screen, the tab is visible and the visitor hasn't asked for less motion. Scroll it away and the loop stops; scroll back and it picks up from the same frame, so there is never a jump.

Reduced motion

With prefers-reduced-motion: reduce, every dither draws one still frame and stays there. The frame is chosen from the middle of the loop, where the pattern is most balanced, and Replay swaps it for another still instead of playing.

Speed and frame rate

Dots are large, so they don't need sixty redraws a second. The defaults keep a full-width hero under 1 ms of work per frame on a mid-range phone.

Usespeedfps
Page background0.088
Hero or card art0.1212
Loading state0.424

Your own loops

Use useDitherClock instead of requestAnimationFrame. It gives you a time value that already respects visibility, reduced motion and the frame rate, so your draw function stays pure.

const t = useDitherClock({ fps: 12 });
draw(ctx, (x, y) => noise(x * .04 + t * .12, y * .04) > bayer(x, y));

Easing and timing

Reveals use one curve, cubic-bezier(.22, 1, .36, 1), over 640 ms. Drift has no easing at all: constant speed reads as weather, while eased loops read as a spinner. See Performance for budgets.
